# Floating origin (work in progress)

This branch contains coordinate arithmetic, a physics shift operation and a renderer previous-view adjustment. Neither is connected to the frame loop, so the engine does not yet provide a floating origin. In particular, `TBD_ORIGIN_THRESHOLD` and `TBD_REBASE_DEBUG` have no effect. Existing scenes, rendering and physics behave as before.

`WorldPosition` holds double-precision absolute coordinates; `ToLocal` subtracts the origin before converting to float, and `PlanOriginShift` proposes a single offset when the local focus exceeds the threshold. A zero threshold disables the proposal. The caller must apply a proposal to every subsystem at a frame boundary before publishing its new origin. Entity coordinates must be retained independently in absolute precision; repeatedly shifting existing float positions cannot recover lost precision. Scene serialization and edits must use absolute coordinates.

The physics operation translates Jolt bodies and the virtual character, refreshes character contacts, and retains collision streaming placements in scene coordinates so later worker results can be localized when added. It must be called on the main thread between physics updates, with the same offset used by all other systems. Scene collision source coordinates are still floats, so their existing precision limits remain. A standalone physics test exercises a static collision, character, dynamic ball, and unload/reload after a shift; worker jobs finishing during a shift and long-running character contact behavior remain untested.

Both renderer backends now share the previous unjittered view-projection matrix, and `Renderer::ShiftPreviousView` changes its coordinate system for TAA and motion-vector reprojection. This operation alone does not fix probe history, cached captures, shadow caches or world-dependent shader effects.

Remaining integration includes scene and camera authority; asynchronous render streaming jobs, entity and instance bounds and GPU instance data; terrain and ground lookup; shadows and cached sun maps; probes and temporal histories; absolute-coordinate vegetation placement, water and clouds; ripples, audio, and play/editor state. The Jolt tree has per-body position setters and a character position setter; a system-wide ShiftOrigin API was not found. Body broadphase updates, velocities, sleeping state and concurrent jobs need explicit validation.

The standalone `tests/floating_origin_test.cpp` exercises threshold and conversion arithmetic over 25 km; its numeric float error example is not a renderer or gameplay test. Required before/after frame comparisons and 20 km scripted runs on D3D12 and Vulkan have not been implemented or run. The frame loop does not call the physics or previous-view operations, and no claim of pop-free rebasing is made.
